## Promotion Video Investigation

### What Was Verified

- Reproduced the promotion-video failure locally using the provided Google credentials.
- Confirmed the current Gemini/Veo API-key path reaches Google but fails with quota exhaustion for Veo generation.
- Confirmed the local machine does not currently have Vertex AI ADC configured, so standard Vertex AI generation cannot complete yet.
- Compared the current backend with the teammate repository `Ohhaeseo/pulse_video` to isolate why that project appears to work.

### Comparison Result

- The teammate project primarily relies on `Vertex AI + ADC` instead of a Gemini free-tier path.
- That repository also returns a sample fallback video URL on failure, which can make a failed Veo request appear successful from the UI.
- PULSE should follow the teammate project's Vertex-oriented execution model, but should keep transparent failure reporting instead of silently returning a sample success payload.

## Promotion Backend Changes

### Backend Defaults

- Switched the promotion-video backend to prefer `Vertex AI` as the default provider whenever `GOOGLE_CLOUD_PROJECT` is configured.
- Changed the Vertex default model baseline to `veo-2.0-generate-001` with `720p`, which is closer to the teammate project's path and less aggressive than the prior Veo 3.1 preview default.
- Disabled secondary backend auto-fallback by default so the backend does not silently bounce between providers and produce confusing mixed failures.

### Auth And Error Handling

- Separated Gemini API and Vertex AI authentication paths more clearly.
- Stopped treating `VERTEX_VIDEO_API_KEY` as if it were a drop-in substitute for standard Vertex AI project authentication.
- Improved promotion error normalization so the API now distinguishes:
  - Gemini quota exhaustion
  - missing Vertex ADC credentials
  - invalid Vertex project/resource mapping
- Preserved explicit failure behavior instead of returning a fake success video when generation fails.

### Prompt Pipeline Stability

- Disabled DSPy prompt optimization when optimizer assets are unavailable, preventing unnecessary quota consumption and noisy partial failures.
- Added local promotion prompt asset files so the promotion prompt service no longer starts with missing-asset warnings.
- Updated `pulse_python/.gitignore` so those promotion asset JSON files can be tracked normally.
