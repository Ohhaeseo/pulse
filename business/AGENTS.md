# AGENTS: 2026 예창패 Business Workspace

이 파일은 `business/` 폴더에서 예비창업패키지 사업계획서, 증빙서류, 시각자료를 다룰 때 적용되는 작업 가이드입니다.

## 우선 참조 순서

아래 자료를 먼저 확인하고 작업합니다.

1. `business/[별첨 4] 2026년 예비창업패키지 예비창업자 모집공고 주요 질의응답.pdf`
2. `business/2026년 예비창업패키지 예비창업자 온라인 사업신청 매뉴얼.pdf`
3. `business/2026년 예비창업패키지 예비창업자 증빙서류 제출목록 안내.docx`
4. `business/[별첨 1] 2026년 예비창업패키지 사업계획서 양식.docx`
5. `business/사업계획서_PULSE_2026_양식정리초안.md`

공식 요건이 불명확할 때는 추측하지 말고, 위 로컬 공식문서와 공식 공고 페이지를 우선 근거로 삼습니다.

## 문체와 개인정보

- 모든 제출용 문안은 기본적으로 `~입니다`, `~합니다` 문체를 사용합니다.
- 대표자·직원 성명, 성별, 생년월일, 대학교명, 직장명 등 개인정보는 제출본 기준으로 마스킹 원칙을 우선 적용합니다.
- 내부 작업 초안에 실명이 있더라도, 제출본으로 변환할 때는 마스킹 여부를 다시 점검합니다.

## 본문과 별첨 분리 원칙

- 사업계획서 본문은 `목차 제외 10페이지 이내`를 우선 제약으로 둡니다.
- 본문에는 `핵심 설득용 이미지`만 남기고, 상세 화면/논문/아키텍처/흐름도는 먼저 `별첨 2 기타 증빙서류` 이동 가능성을 검토합니다.
- 기본 원칙:
  - 본문: 서비스 요약, MVP 대표 화면, 비즈니스 모델 또는 로드맵
  - 별첨 2: KCI 논문, MVP 상세 화면, 기술 아키텍처, 사용자 흐름도

## 한글 DOCX 생성 원칙

- 한글이 포함된 `.docx`는 `python-docx` 기반으로 생성하거나 수정합니다.
- PowerShell here-string, shell redirection, 인라인 echo 방식으로 한글 문서를 직접 생성하지 않습니다.
- 템플릿 기반 문서는 원본을 덮어쓰지 말고 출력본을 별도 파일로 저장합니다.
- 생성 후에는 `python-docx`로 다시 열어 핵심 텍스트와 표 셀 내용을 검증합니다.
- 렌더링 도구가 없으면 레이아웃 리스크를 명시합니다.

## PNG/도식 생성 원칙

- 사업계획서용 PNG는 `images/`에 저장합니다.
- 카드형 도식은 텍스트 overflow, 줄바꿈, 정렬을 반드시 검수합니다.
- 생성 스크립트는 `business/` 아래에 보관해 재생성 가능하게 유지합니다.
- 첫 결과물이 어색하면 바로 재렌더링하고, “초안” 상태를 최종본처럼 넘기지 않습니다.

## 선호하는 작업 방식

- 반복 작업은 스크립트로 남깁니다.
- 제출 순서가 있는 문서는 `[붙임 1]`, `[붙임 7-1]` 같은 라벨을 유지합니다.
- 사업계획서, 별첨, 이미지 가이드는 서로 모순되지 않게 함께 갱신합니다.
